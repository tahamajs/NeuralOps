    Title & Subtitle

    Rotational SliceGPT-INT4: Orthogonal Basis Transformation Meets Structured Weight Slicing
    Rotating activation coordinate systems via orthogonal transformation matrices to concentrate signal energy, physically slicing away redundant channels, and quantizing the dense core to INT4.

    The Analogy

    Imagine packing an oddly shaped, sprawling collection of luggage into a tight cargo trunk. If you throw the items in at random angles, they bump into each other, creating dead space and sticking out of the edges. But if you first rotate every suitcase to align perfectly with a geometric grid (orthogonal rotation), all the heavy mass settles tightly into the first 75% of the trunk. You can then slice off the empty remaining 25% of the trunk compartment entirely, and vacuum-pack the rest (INT4 quantization) without crushing a single fragile item.

    The Problem

    Traditional pruning algorithms fall into two extremes, both of which struggle on modern hardware: 1. Unstructured Sparsity: Zeroes out arbitrary individual weights. While this retains model accuracy, modern GPU Tensor Cores cannot execute irregular sparse patterns efficiently without specialized sparse libraries that introduce severe latency overhead. 2. Standard Structured Pruning: Drops entire weight columns or attention heads to produce smaller, dense matrices. However, large language models develop complex inter-channel dependencies and extreme activation outliers. Naively dropping channels destroys critical representations, causing catastrophic perplexity degradation unless recovered by expensive full-scale retraining.

    How It Works (The Intuition)

    Rotational SliceGPT solves this dilemma through a two-phase mathematical transformation: 1. Orthogonal Basis Rotation: Using Singular Value Decomposition (SVD) or Principal Component Analysis (PCA) on calibration activations, we compute an orthogonal transformation matrix \(Q \in \mathbb{R}^{d \times d}\) (where \(Q^T Q = I\)). Because \(Q\) is strictly orthogonal, inserting \(Q Q^T\) between linear layers and normalization layers does not alter the mathematical output of the network. 2. Energy Concentration: The rotation rotates the coordinate system of the activations such that signal variance is sorted in descending order. The first \(k\) dimensions (e.g., \(k = 3072\) out of \(d = 4096\)) retain over \(98\%\) of the total activation variance, while the trailing \(d - k\) dimensions decay close to zero. 3. Structured Slicing: The model physically truncates the weight matrices from \(d \times d\) down to \(k \times k\). The unneeded channels are deleted from VRAM permanently, reducing the physical dimensions of all linear layers. 4. INT4 Quantization: The remaining compact \(k \times k\) dense core is quantized to 4-bit integers using group-wise symmetric uniform quantization.

    flowchart LR
    A["Input Tokens X"] --> B["Orthogonal Rotation Q"]
    B --> C["Rotated Space XQ"]
    C --> D["Variance Slicing: Keep top-k"]
    D --> E["INT4 Quantization W_sliced"]
    E --> F["Ultra-Fast Dense INT4 Tensor Core"]

    The Math (Light)

    Given an activation matrix \(X \in \mathbb{R}^{T \times d}\) and linear weight \(W \in \mathbb{R}^{d \times d_{\text{out}}}\), we insert the identity \(I = Q Q^T\): $\(Y = X W = (X Q) (Q^T W) = \tilde{X} \tilde{W}\)$ We compute \(Q\) from the eigenvalue decomposition of the activation covariance matrix \(C = \frac{1}{T} X^T X = Q \Lambda Q^T\).
    By selecting the top-\(k\) principal components, we slice the rotated weight: $\(\tilde{W}_{\text{sliced}} = (Q^T W)_{[:k, :]} \in \mathbb{R}^{k \times d_{\text{out}}}\)$ We then quantize \(\tilde{W}_{\text{sliced}}\) into 4-bit signed integers with scaling factor \(S\): $\(W_{\text{INT4}} = \text{clamp}\left( \left\lfloor \frac{\tilde{W}_{\text{sliced}}}{S} \right\rceil, -8, 7 \right), \quad S = \frac{\max(|\tilde{W}_{\text{sliced}}|)}{7}\)$

    Why It Matters

    • Physical Tensor Shrinkage: Slicing 25% of hidden dimensions cuts parameter count and FLOPs by \((1 - 0.75^2) \approx 43.7\%\) before quantization.
    • Hardware-Native Dense Execution: The pruned model runs on standard cuBLAS and CUTLASS dense GEMM kernels with zero sparse indexing penalties.
    • 5.3x Total Compression: Combining a 25% slice with INT4 quantization reduces a 70B parameter model footprint from 140 GB (FP16) down to ~26 GB, fitting on a single 32 GB workstation GPU with negligible perplexity loss.

    Title & Subtitle

    DeltaKV & CacheNotes: Dynamic Key-Value Differential Compression
    Exploiting cross-token contextual redundancy in generative decoding by storing anchor keyframes, ultra-low-bit delta residuals, and hierarchical semantic notes.

    The Analogy

    Consider modern video streaming formats like H.265 (HEVC). The video player does not store a full, uncompressed 4K image for every single 60-fps frame (I-frames). Instead, it stores one high-fidelity reference frame every few seconds, followed by tiny differential motion vectors (P-frames and B-frames) that describe only what changed. DeltaKV applies video codec delta-compression to the Key-Value cache of large language models: it keeps rare anchor tokens in high precision and stores the subsequent 90% of tokens as micro-precision residual deltas.

    The Problem

    During autoregressive text generation, the Key-Value (KV) cache grows linearly with context length (\(O(B \cdot L \cdot H \cdot D)\)). For a 70B model operating at a 128k context window: - The KV cache demands >160 GB of VRAM, far exceeding the memory required by the model weights themselves! - Memory bandwidth saturation from reading this massive KV cache during every single decoding step throttles generation speed down to single-digit tokens per second.

    How It Works (The Intuition)

    1. Anchor Token Identification: When a new prompt or sequence is processed, tokens with high semantic saliency or periodic interval tokens (every \(N\) tokens) are designated as Anchor Keys and Values (\(K_{\text{base}}, V_{\text{base}}\)) and kept in FP8/FP16.
    2. Differential Residual Formulation: For intermediate tokens \(t\), the attention key and value vectors are highly correlated with the local anchor. DeltaKV computes the difference vector: $\(\Delta K_t = K_t - K_{\text{base}}, \quad \Delta V_t = V_t - V_{\text{base}}\)$
    3. 2-Bit / 3-Bit Residual Quantization: Because \(\Delta K_t\) and \(\Delta V_t\) are tightly clustered around zero with minimal variance, they can be aggressively quantized to 2-bit or 3-bit non-linear integer grids without loss of fidelity.
    4. CacheNotes Hierarchical Summarization: As context recedes into the distant past (\(>4096\) tokens back), DeltaKV merges clusters of delta tokens into a single compact low-rank "CacheNote" centroid vector, freeing up cache lines while retaining long-range associative recall.
    sequenceDiagram
    participant LLM as Decoder Layer
    participant Anchor as Anchor Buffer (FP16/FP8)
    participant Delta as Delta Storage (2-bit INT)
    participant Notes as CacheNotes Engine

    LLM->>Anchor: Write Keyframe Token (t=0)
    LLM->>Delta: Compute & Quantize Delta ΔK, ΔV (t=1..7)
    Note over Delta: 2-bit Non-linear Quantization
    LLM->>Notes: Background: Compress Past Blocks into Semantic Centroid
    LLM->>LLM: Fast Reconstructed Dequant Decode: K = K_anchor + dequant(ΔK)

    The Math (Light)

    Let \(K_t \in \mathbb{R}^{d_k}\) be the key vector at time \(t\) and \(K_{\text{anchor}}\) be its assigned reference key. The quantized residual representation is: $\(\mathbf{q}_t = \mathcal{Q}_{b\text{-bit}}\left( K_t - K_{\text{anchor}} \right) = \left\lfloor \frac{K_t - K_{\text{anchor}}}{s_t} \right\rceil\)$ During the attention score calculation between query \(Q_{\tau}\) and cached key \(K_t\), the dot product expands linearly: $\(\text{AttnScore}(\tau, t) = \frac{Q_{\tau} K_t^T}{\sqrt{d_k}} = \frac{Q_{\tau} K_{\text{anchor}}^T}{\sqrt{d_k}} + \frac{Q_{\tau} \left( s_t \cdot \mathbf{q}_t \right)^T}{\sqrt{d_k}}\)$ Because \(Q_{\tau} K_{\text{anchor}}^T\) can be pre-computed or shared across clustered tokens, the inner loop computes low-precision integer dot products against \(\mathbf{q}_t\).

    Why It Matters

    • 4x to 6x KV Cache Reduction: Reduces 128k context KV memory footprint from 160 GB down to ~32 GB.
    • 3.2x Decoding Throughput: Massive reduction in memory bandwidth traffic allows GPU compute engines to run closer to peak FLOPS.
    • Zero Hallucination on Needle-In-A-Haystack: Unlike naive token dropping, DeltaKV preserves every single token's position and gradient direction in residual space.

    Title & Subtitle

    ZeroKV-Neo: Zero-Footprint Persistent Memory with Dynamic Eviction & State Recurrence
    Achieving constant O(1) KV cache memory bounds during infinite-horizon generation by combining attention-sink preservation, dynamic mass eviction, and recurrent summary compression.

    The Analogy

    Imagine a courtroom stenographer working on a 6-month trial. If they tried to keep every single open sheet of paper spread out across the courtroom floor, they would run out of physical space within days. Instead, a master stenographer keeps: 1. The original charge sheet pinned to the front podium (Attention Sinks), 2. The active testimony from the current witness (Local Sliding Window), 3. Key exhibits that are frequently referenced (Heavy Hitters), and 4. Summarizes all resolved daily arguments into an ongoing master case ledger (Recurrent Summary State), recycling the scratch paper.

    The Problem

    Autoregressive transformers suffer from the Infinite Context Memory Wall. If a model generates text continuously (such as in autonomous agent loops, continuous streaming chat, or real-time sensor processing), the KV cache will eventually exhaust GPU VRAM, leading to out-of-memory (OOM) crashes. Simple sliding-window cache strategies fail catastrophically: when early tokens (especially the first 4 tokens) are evicted, the model exhibits sudden, complete perplexity collapse due to the loss of "attention sinks."

    How It Works (The Intuition)

    ZeroKV-Neo establishes a bounded, constant-size memory architecture: 1. Permanent Attention Sinks: The initial 4 tokens (\(t \in [0, 3]\)) are permanently locked in high-precision cache. They absorb surplus softmax attention scores and prevent numerical instability. 2. Cumulative Attribution Scoring: For all intermediate tokens, ZeroKV-Neo tracks an exponential moving average (EMA) of attention scores received from recent queries: $\(S_i^{(t)} = \beta S_i^{(t-1)} + (1 - \beta) \sum_{h=1}^H A_{h, t, i}\)$ 3. Dynamic Heavy-Hitter Retention: Tokens with high cumulative attribution scores are retained in the active cache pool. 4. Recurrent Summary Eviction: When a token's attribution score drops below an eviction threshold, it is not simply deleted. Instead, its Value vector is projected and blended into a fixed-size recurrent state vector \(h_{\text{neo}} \in \mathbb{R}^{d}\), preserving background semantic context in \(O(1)\) memory.

    flowchart TD
    In["New Token Query Q_t"] --> Attn["Compute Attention Over Cache"]
    Attn --> UpScore["Update Attribution Score S_i for all tokens"]
    UpScore --> Check{"Memory Limit Exceeded?"}
    Check -- No --> Store["Append to Cache"]
    Check -- Yes --> Split["Partition Cache"]
    Split --> Sinks["Keep Pinned Initial Sinks (0..3)"]
    Split --> Local["Keep Recent Window (t-W .. t)"]
    Split --> TopK["Select Top-K Highest S_i"]
    Split --> Evict["Evict Low-Scoring Tail"]
    Evict --> Compress["Blend into Recurrent Summary Vector h_neo"]

    The Math (Light)

    The active key-value cache indices \(\mathcal{M}_t\) at step \(t\) are dynamically maintained under a strict budget \(B\): $\(\mathcal{M}_t = \underbrace{\{0, 1, 2, 3\}}_{\text{Attention Sinks}} \;\cup\; \underbrace{\{t-W, \dots, t\}}_{\text{Recent Sliding Window}} \;\cup\; \text{TopK}_{B - W - 4}\left( \left\{ S_i^{(t)} \;\middle|\; i \in [4, t-W-1] \right\} \right)\)$ For evicted token indices \(\mathcal{E}_t\), the recurrent summary vector \(h_{\text{neo}}\) is updated via gated recurrent absorption: $\(h_{\text{neo}}^{(t)} = \alpha_t h_{\text{neo}}^{(t-1)} + (1 - \alpha_t) \sum_{j \in \mathcal{E}_t} \left( \frac{S_j^{(t)}}{\sum_{k \in \mathcal{E}_t} S_k^{(t)}} \right) V_j\)$ During attention, \(h_{\text{neo}}\) is appended as a single virtual token at position 4.

    Why It Matters

    • True \(O(1)\) Memory Consumption: Guarantees fixed VRAM usage whether generating 1,000 tokens or 10,000,000 tokens.
    • Infinite Streaming on Edge Devices: Allows running a 7B/13B parameter chatbot continuously on an 8 GB VRAM laptop or mobile chip without memory leaks or degradation.
    • Zero Softmax Collapse: Retains baseline perplexity across multi-day streaming sessions.

    Title & Subtitle

    FLAP: Fluctuation-Aware Structured Pruning without Retraining
    Eliminating entire transformer channels and heads by evaluating output variance fluctuations and absorbing static baseline biases into downstream layers.

    The Analogy

    Imagine a control panel with 100 indicator dials monitoring a chemical plant. If 30 of those dials constantly point to "5.0" regardless of whether the plant is running at idle, full blast, or in an emergency, those 30 dials are not providing dynamic information—they are just reporting a static baseline. You can safely remove those 30 dials, wire their constant "+5.0" signal directly into the alarm logic (bias compensation), and focus the control room's attention entirely on the 70 dials that actively fluctuate with real-world changes.

    The Problem

    Traditional structured pruning relies on weight magnitude heuristics (e.g., pruning weight rows with the smallest \(L_1\) or \(L_2\) norm). In modern LLMs with RMSNorm and residual connections, this fails for two major reasons: 1. Large weight values often serve merely to cancel out constant baseline offsets, producing zero dynamic variance. 2. Channels with small weight norms often carry critical, high-frequency signals that govern fine-grained logical reasoning. Pruning based on weight magnitude alone rips out sensitive dynamic channels, destroying the model's reasoning capabilities unless repaired by expensive multi-epoch retraining.

    How It Works (The Intuition)

    1. Sampling Dynamic Fluctuations: Pass a small calibration dataset (e.g., 128 sequences from C4) through the model and record post-activation feature maps \(X_{:, i}\) for each channel \(i\).
    2. Variance vs. Bias Decomposition: Decompose each channel into its static mean component \(\mu_i = \mathbb{E}[X_{:, i}]\) and its dynamic fluctuation \(\sigma_i^2 = \text{Var}(X_{:, i})\).
    3. Bias Compensation Fusion: For channels with near-zero fluctuation \(\sigma_i \approx 0\), their static contribution is completely predictable. When channel \(i\) is removed from weight matrix \(W\), its mean contribution \(\mu_i W_{i, :}\) is added directly into the downstream layer's bias vector: $\(b_{\text{new}} = b_{\text{old}} + \sum_{i \in \text{Pruned}} \mu_i W_{i, :}\)$
    4. Structured Dimension Truncation: Channels, heads, or MLP intermediate widths are ranked by their dynamic impact score \(I_i = \sigma_i \cdot \|W_{i, :}\|_2\), and the lowest-scoring dimensions are physically sliced out.
    flowchart LR
    A["Calibration Data"] --> B["Compute Feature Mean μ & Variance σ²"]
    B --> C{"Is Variance σ² Significant?"}
    C -- "High Fluctuation" --> D["Retain Dynamic Channel in Dense Matrix"]
    C -- "Low Fluctuation" --> E["Prune Channel from Weight Tensor"]
    E --> F["Fuse Static Bias Contribution (μ * W) into Layer Bias"]
    D & F --> G["Compensated Pruned Model (Zero Retraining Required)"]

    The Math (Light)

    Given a linear projection \(Y = X W + b\), where \(X \in \mathbb{R}^{T \times d_{\text{in}}}\) and \(W \in \mathbb{R}^{d_{\text{in}} \times d_{\text{out}}}\), the contribution of channel \(i\) is \(X_{:, i} W_{i, :}\).
    We express \(X_{:, i}\) in terms of its mean and deviation: \(X_{:, i} = \mu_i + \Delta X_{:, i}\), where \(\mathbb{E}[\Delta X_{:, i}] = 0\) and \(\text{Var}(\Delta X_{:, i}) = \sigma_i^2\).
    The layer output becomes: $\(Y = \sum_{i \in \text{Retained}} X_{:, i} W_{i, :} + \underbrace{\sum_{j \in \text{Pruned}} \mu_j W_{j, :} + b}_{\text{Updated Bias } b^*} + \underbrace{\sum_{j \in \text{Pruned}} \Delta X_{:, j} W_{j, :}}_{\text{Reconstruction Error } \mathcal{E}}\)$ The Fluctuation-Aware Metric minimizes the error \(\mathbb{E}[\|\mathcal{E}\|_2^2]\) by selecting channels to maximize: $\(I_i = \sigma_i \cdot \|W_{i, :}\|_2\)$

    Why It Matters

    • True Zero-Retraining Structured Pruning: Reduces model size by 20% to 30% in minutes on a single GPU without requiring fine-tuning datasets or gradient updates.
    • Hardware Agnostic Acceleration: Produces standard, smaller dense matrices that immediately accelerate inference on any backend (PyTorch, vLLM, TensorRT-LLM, Apple Silicon).
    • Exact DC Bias Preservation: Prevents distribution shift in deep residual networks.

    Title & Subtitle

    ARMOR & Wanda: Pruning by Weights and Activations without Optimization
    Evaluating weight importance through the element-wise product of static weight magnitudes and dynamic input activation norms for rapid, one-shot sparsification.

    The Analogy

    Imagine judging the productivity of a bridge's structural cables. If you only look at the thickness of a cable (weight magnitude \(|W|\)), you might cut a thin cable. But if that thin cable happens to carry a high-voltage power line delivering electricity to an entire city (input activation norm \(\|X\|_2\)), cutting it causes an instant blackout! Wanda ensures you never cut a wire without checking how much current is actively flowing through it.

    The Problem

    Historically, pruning large language models required either: - Magnitude Pruning (\(|W|\)): Fast, but causes catastrophic perplexity spikes at \(>30\%\) sparsity because it ignores activation outliers (isolated channels that have activation values up to 100x larger than normal). - Hessian / Second-Order Methods (SparseGPT / OBS): Highly accurate, but computationally expensive because they require computing, storing, and inverting giant Hessian matrices (\(H = X X^T\)) for every layer, which can encounter numerical instability on massive models.

    How It Works (The Intuition)

    Wanda (Weights and Activations) and its robust adaptive counterpart ARMOR recognize that the output impact of any weight \(W_{ij}\) is directly proportional to both its own absolute magnitude and the \(L_2\) norm of the input feature channel \(j\) feeding into it: 1. Pass Calibration Data: Run a forward pass of 128 sequences through the model and compute the aggregate \(L_2\) norm for each input feature dimension \(j\): $\(s_j = \|X_{:, j}\|_2 = \sqrt{\sum_{t=1}^T X_{t, j}^2}\)$ 2. Compute Joint Importance: For every weight entry \(W_{ij}\) (row \(i\), column \(j\)), compute the joint importance metric: $\(S_{ij} = |W_{ij}| \cdot s_j\)$ 3. Per-Output Pruning: Compare scores locally across each row \(i\). For 50% unstructured pruning or 2:4 semi-structured sparsity, zero out the lowest-scoring weights within each row or 4-element window. 4. ARMOR Robustness: ARMOR introduces adaptive outlier shielding and local gradient-free residual compensation across surviving adjacent weights to prevent cumulative layer-to-layer drift.

    flowchart LR
    A["Input Activation Tensor X"] --> B["Compute Column-wise L2 Norm: ||X_j||_2"]
    C["Weight Matrix W"] --> D["Compute Absolute Magnitude: |W_ij|"]
    B & D --> E["Wanda Saliency Matrix: S_ij = |W_ij| * ||X_j||_2"]
    E --> F["Apply 2:4 or Unstructured Mask per Row"]
    F --> G["ARMOR Residual Local Compensation"]
    G --> H["Deployable Sparse Model"]

    The Math (Light)

    The output component \(Y_i\) generated by row \(i\) of weight matrix \(W\) is: $\(Y_i = \sum_{j=1}^{d_{\text{in}}} W_{ij} X_j\)$ By Cauchy-Schwarz inequality, the maximum error \(\Delta Y_i\) induced by setting \(W_{ij} = 0\) is bounded by: $\(|\Delta Y_i| \le |W_{ij}| \cdot \|X_j\|_2\)$ Thus, the Wanda importance score is defined as: $\(S_{ij} = |W_{ij}| \cdot \|X_{:, j}\|_2 = |W_{ij}| \cdot \sqrt{\frac{1}{T} \sum_{t=1}^T X_{t, j}^2}\)$ The pruning mask \(M \in \{0, 1\}^{d_{\text{out}} \times d_{\text{in}}}\) is obtained by: $\(M_{ij} = \mathbf{1}\left( S_{ij} \ge \text{Quantile}_p\left( S_{i, :} \right) \right)\)$

    Why It Matters

    • 100x Faster than Second-Order Methods: Prunes a 65B/70B model in under 10 seconds on a single GPU with zero matrix inversions.
    • Outlier Protection: Naturally protects all weights connected to activation outlier channels, preventing the reasoning collapse that plagues magnitude pruning.
    • Seamless 2:4 Sparsity Generation: Directly produces 2:4 sparsity patterns ready for hardware acceleration on NVIDIA Tensor Cores.

    Title & Subtitle

    SparseGPT: One-Shot Inversion for 2:4 Hardware-Accelerated Sparsity
    Solving the layer-wise Optimal Brain Surgeon problem at scale using block Cholesky decomposition to achieve 2x Tensor Core throughput with zero retraining.

    The Analogy

    Imagine a delicate game of giant Jenga. If you walk up to the tower and randomly kick out 50% of the wooden blocks, the entire tower will crash to the ground. However, if a structural engineer uses a precision laser to measure the exact load stress across every beam, carefully slides out 2 blocks from every row of 4, and instantly micro-adjusts the remaining 2 blocks by a fraction of a millimeter to redistribute the load, the tower remains standing at 100% stability while weighing half as much.

    The Problem

    While unstructured 50% sparsity saves theoretical operations, modern GPU architectures (NVIDIA Ampere, Ada Lovelace, Hopper, Blackwell) cannot accelerate arbitrary sparse matrices—they require dense, coalesced memory access. To bridge this gap, modern GPUs introduced 2:4 Semi-Structured Sparse Tensor Cores, which double math throughput if and only if exactly 2 out of every 4 consecutive values in a weight row are zero.
    However, finding the optimal 2:4 pattern naively creates severe cumulative error, destroying complex LLM benchmark performance across deep layers.

    How It Works (The Intuition)

    SparseGPT frames structured 2:4 pruning as a constrained quadratic optimization problem: $\(\min_{\hat{W}} \| W X - \hat{W} X \|_2^2 \quad \text{s.t. } \hat{W} \text{ satisfies 2:4 sparsity}\)$ 1. Inverse Hessian Computation: The algorithm computes the activation correlation matrix \(H = 2 X X^T + \lambda I\) and its inverse \(H^{-1}\) using stable Cholesky decomposition. 2. Block-Wise Column Updates: Rather than updating weights one by one (which would require millions of matrix updates), SparseGPT processes columns in blocks (e.g., \(B = 128\) columns at a time). 3. Optimal 2:4 Selection: For each 4-element window, SparseGPT evaluates all \(\binom{4}{2} = 6\) possible pruning combinations and selects the pair that minimizes reconstruction loss weighted by \([H^{-1}]_{pp}\). 4. Surviving Weight Compensation: The moment 2 weights are pruned, SparseGPT immediately updates all remaining unpruned weights in the row using the closed-form Optimal Brain Surgeon formula, canceling out the mathematical error before moving to the next block.

    B --> C["Iterate over Column Blocks (B=128)"]
    C --> D["For every 4 weights: Pick optimal 2 to prune via (W_p)^2 / [H^-1]_pp"]
    D --> E["OBS Weight Compensation: Update unpruned weights via Error Vector"]
    E --> F{"More Blocks?"}
    F -- Yes --> C
    F -- No --> G["Export Native 2:4 Sparse Weights + Metadata to Tensor Cores"]

    The Math (Light)

    Let \(H = 2 X X^T\) be the Hessian of the layer loss. When weight \(w_q\) at index \(q\) is pruned (\(w_q \to 0\)), the optimal compensation update \(\delta W\) for all surviving weights in the layer is given by: $\(\delta W = - \frac{w_q}{\left[ H^{-1} \right]_{qq}} \cdot \left( H^{-1} \right)_{:, q}\)$ The resulting increase in reconstruction error is: $\(\Delta E = \frac{1}{2} \frac{w_q^2}{\left[ H^{-1} \right]_{qq}}\)$ For 2:4 sparsity, SparseGPT groups columns into sets of 4, computes \(\Delta E\) for all \(\binom{4}{2} = 6\) masks, selects the minimum-error mask, and applies the vectorized OBS update across the remaining dense block.

    Why It Matters

    • True 2x GEMM Speedup: Directly unlocks the hardware 2:4 Sparse Tensor Cores in NVIDIA RTX 3090/4090, A100, and H100 GPUs.
    • 50% Memory Footprint: Compresses FP16 weight tensors into half their original byte size by storing only non-zero values and 2-bit index metadata.
    • Negligible Perplexity Impact: Retains \(>99\%\) of baseline zero-shot accuracy on massive 70B models (LLaMA-3, Mistral) without a single step of gradient backpropagation.

    Title & Subtitle

    SmoothQuant & AWQ: Outlier Migration and Activation-Aware Weight Quantization
    Taming activation outliers by mathematically shifting dynamic range from activations to weights, and shielding salient weight channels for zero-degradation 4-bit inference.

    The Analogy

    Imagine trying to pack two items into identical rigid boxes: a soft foam pillow (smooth weights) and an iron sculpture with one sharp 3-foot spike sticking out (activation outliers). Trying to force the spiky sculpture into the small box crushes the spike and breaks the box (clipping error). SmoothQuant takes a file and gently files down the iron spike, using the iron filings to reinforce the soft pillow. Both items end up smooth, moderately sized, and fit into standard boxes (INT8/INT4) without breaking anything.

    The Problem

    Post-training quantization of LLMs encounters a massive roadblock: Activation Outliers. - While weight tensors have smooth, Gaussian-like distributions that are easy to quantize to INT8 or INT4, activation tensors develop persistent outlier channels with magnitudes up to 100x larger than normal values. - In per-tensor or per-token activation quantization, these rare outlier spikes force the quantization scale factor \(S\) to be very large, effectively rounding all normal tokens to 0 or 1 and destroying model reasoning.

    How It Works (The Intuition)

    1. SmoothQuant (Activation-to-Weight Migration): SmoothQuant observes that a linear layer \(Y = X W\) can be scaled by an arbitrary diagonal matrix \(s \in \mathbb{R}^d\) without changing the output: $\(Y = (X \cdot \text{diag}(s)^{-1}) \cdot (\text{diag}(s) \cdot W) = \hat{X} \hat{W}\)$ By setting \(s_j = \frac{\max(|X_j|)^\alpha}{\max(|W_j|)^{1-\alpha}}\) (with migration strength \(\alpha \approx 0.5\)), SmoothQuant divides the spiky activation channel by \(s_j\) while multiplying the corresponding weight column by \(s_j\). This balances the dynamic ranges so both activations and weights can be cleanly quantized to INT8 (W8A8).
    2. AWQ (Activation-Aware Weight Quantization): AWQ observes that not all weights are equally important: only the top \(1\%\) of weight channels that interact with large activation magnitudes dictate perplexity. Instead of keeping those salient channels in FP16 (which ruins GPU memory alignment), AWQ searches for an optimal per-channel protection scale \(s^*\) that minimizes the reconstruction error of the output feature map under INT4 weight quantization: $\(W' = W \cdot \text{diag}(s), \quad X' = \text{diag}(s)^{-1} \cdot X\)$
    flowchart LR
    A["Raw Activations X (Has Outliers)"] --> B["Calculate Per-Channel Outlier Saliency s_j"]
    C["Raw Weights W"] --> D["Scale Weights: W_hat = diag(s) * W"]
    B --> E["Scale Activations: X_hat = X * diag(s)^-1"]
    D --> F["INT4/INT8 Quantized Weight Matrix"]
    E --> G["INT8 Quantized Activation Stream"]
    F & G --> H["Fast W8A8 / W4A16 Tensor Core GEMM Engine"]

    The Math (Light)

    The SmoothQuant per-channel migration scale \(s \in \mathbb{R}^{d_{\text{in}}}\) is defined as: $\(s_j = \frac{\left( \max_{t} |X_{t, j}| \right)^\alpha}{\left( \max_{i} |W_{i, j}| \right)^{1-\alpha}}, \quad \alpha \in [0, 1]\)$ - \(\alpha = 1\): Pushes all quantization difficulty to weights. - \(\alpha = 0\): Pushes all quantization difficulty to activations. - \(\alpha = 0.5\): Optimal geometric balance between activation and weight dynamic ranges.

    For AWQ, the optimal scaling vector \(s^*\) is found by minimizing the Frobenius norm: $\(s^* = \arg\min_{s} \left\| W X - \mathcal{Q}\left( W \cdot \text{diag}(s) \right) \cdot \text{diag}(s)^{-1} X \right\|_F^2\)$ where \(\mathcal{Q}(W) = \text{clamp}\left( \left\lfloor \frac{W}{S} \right\rceil, -2^{b-1}, 2^{b-1}-1 \right) \cdot S\).

    Why It Matters

    • SmoothQuant: Enables full W8A8 (INT8 weights + INT8 activations) integer matrix multiplication on GPU Tensor Cores, doubling throughput and cutting memory in half with zero loss in accuracy.
    • AWQ: The industry-standard foundation for W4A16 (INT4 weights + FP16 activations) inference (used across vLLM, HuggingFace TGI, AutoAWQ), delivering 3.5x faster generation on memory-bound workloads.

    Title & Subtitle

    Squeezing Heads Distillation: Structured Head Pruning with Cross-Layer Distillation
    Pruning redundant multi-head attention mechanisms and compressing deep multi-head layers into compact student models via attention-map and hidden-state transfer.

    The Analogy

    Imagine a corporate advisory board with 32 consultants. During meetings, 20 of them simply repeat or rephrase what the top 8 consultants have already stated, creating immense noise, scheduling delays, and high payroll costs. Squeezing Heads Distillation identifies the 8 master thinkers, trains them through intensive mentoring (cross-layer distillation) to absorb all subtle secondary perspectives of the entire original 32-person board, and dissolves the redundant seats, allowing decisions to be made 4x faster with zero loss in strategic depth.

    The Problem

    Modern Large Language Models allocate 32 to 64 attention heads per layer. Empirical research reveals that: - Many heads exhibit identical attention patterns (e.g., simple previous-token lookups or uniform broadcast). - Each attention head requires dedicated projection weights (\(W_q, W_k, W_v, W_o\)) and allocates an independent Key-Value cache line. - Naively deleting heads causes catastrophic degradation on reasoning tasks, while training a smaller model from scratch costs hundreds of thousands of dollars in compute.

    How It Works (The Intuition)

    Squeezing Heads Distillation combines Taylor-expansion head ranking with a multi-objective distillation pipeline: 1. First-Order Head Importance Estimation: Measure how sensitive the validation loss is to the removal of head \(h\): $\(I_h = \sum_{t=1}^T \left| \frac{\partial \mathcal{L}}{\partial \text{Head}_h(t)} \cdot \text{Head}_h(t) \right|\)$ 2. Head Squeezing & Grouping: The least important heads are progressively pruned, collapsing the architecture (e.g., from 32 heads down to 8 heads, or converting Multi-Head Attention into compact Grouped-Query Attention). 3. Multi-Tier Distillation Objective: - Attention Map Distillation: Student attention matrices \(A^S\) are trained to match the attention distribution of the teacher \(A^T\) via Kullback-Leibler (KL) divergence. - Hidden State Alignment: Student layer outputs are projected and aligned with teacher representations using Mean Squared Error (MSE) loss. - Logit Matching: Soft target probabilities are matched using temperature-scaled cross-entropy.

    Teacher["Teacher Layer (32 Heads)"] --> Imp["Compute Head Importance Attribution I_h"]
    Imp --> Prune["Prune Bottom 75% Heads (32 -> 8)"]
    Prune --> Student["Student Layer (8 Squeezed Heads)"]
    Teacher -- "Teacher Attention Maps A^T" --> L_attn["KL Divergence Loss"]
    Student -- "Student Attention Maps A^S" --> L_attn
    Teacher -- "Teacher Hidden States H^T" --> L_mse["Projected MSE Loss"]
    Student -- "Student Hidden States H^S" --> L_mse
    L_attn & L_mse --> L_tot["Total Distillation Loss: Train Student Weights"]

    The Math (Light)

    The composite distillation objective function \(\mathcal{L}_{\text{total}}\) is formulated as: $\(\mathcal{L}_{\text{total}} = (1 - \lambda) \mathcal{L}_{\text{CE}}(y, \hat{y}_S) + \lambda T^2 \mathcal{L}_{\text{KL}}\left( \sigma\left(\frac{z_T}{T}\right) \;\middle\|\; \sigma\left(\frac{z_S}{T}\right) \right) + \gamma \mathcal{L}_{\text{Attn}} + \beta \mathcal{L}_{\text{Hidden}}\)$ Where the Attention Map Distillation Loss \(\mathcal{L}_{\text{Attn}}\) across selected layer pairs \((l_T, l_S)\) is: $\(\mathcal{L}_{\text{Attn}} = \sum_{i=1}^{H_S} D_{\text{KL}}\left( A_{l_T, \phi(i)}^T \;\middle\|\; A_{l_S, i}^S \right)\)$ And the Hidden State Alignment Loss \(\mathcal{L}_{\text{Hidden}}\) using learned projection matrix \(W_{\text{proj}}\) is: $\(\mathcal{L}_{\text{Hidden}} = \left\| H_{l_T}^T - W_{\text{proj}} H_{l_S}^S \right\|_F^2\)$

    Why It Matters

    • 4x Reduction in KV Cache Size: Pruning from 32 heads to 8 heads directly quarters the runtime KV memory requirement.
    • 2.5x Decode Latency Acceleration: Smaller projections and reduced memory traffic dramatically speed up autoregressive decoding.
    • Sample-Efficient Recovery: Recovers 99%+ of original teacher benchmark accuracy with only 1% to 2% of original pre-training tokens.

    Title & Subtitle

    CoOpQ: Coordinated Heterogeneous Quantization with Mixed-Format INT4/FP4 Matrix Engines
    Co-optimizing distinct numerical data types across transformer sub-modules to achieve optimal dynamic range retention, maximum integer compute density, and sub-4-bit effective precision.

    The Analogy

    Think of a Formula 1 racing car powertrain. It does not use only an electric battery or only an internal combustion engine. It uses a hybrid cooperative powertrain: the high-torque electric motor delivers instant zero-RPM acceleration (uniform INT4 for massive attention matrix multiplication), while the high-RPM turbocharged engine delivers top-end power across a wide dynamic rev range (floating-point FP4/FP8 for non-linear MLP expansion). The central computer coordinates both engines seamlessly in real time.

    The Problem

    One-size-fits-all quantization enforces the same numerical format across every layer in a transformer: - Pure INT4 Quantization excels at linear projection layers with bounded values, but severely clips the heavy-tailed, non-linear activations inside MLP SwiGLU layers. - Pure FP4 (E2M1) Quantization handles wide dynamic ranges and outliers in MLP layers, but suffers from lower signal-to-noise ratio (SNR) on uniform attention weights due to having only 1 mantissa bit. Forcing an entire model into one format leads to unnecessary perplexity loss or under-utilizes hardware compute capabilities.

    How It Works (The Intuition)

    CoOpQ (Cooperative Optimized Quantization) assigns mathematically specialized numerical representations to each distinct transformer sub-module based on empirical loss sensitivity: 1. Attention Projections (\(W_q, W_k, W_v, W_o\)) \(\to\) INT4-Symmetric: Attention weights exhibit uniform, zero-centered distributions. CoOpQ maps them to INT4 with fine-grained group scaling (\(G=64\)), maximizing raw arithmetic throughput on integer ALUs. 2. MLP SwiGLU Blocks (\(W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}\)) \(\to\) FP4 (E2M1): Gated feed-forward layers generate wide dynamic activation ranges. CoOpQ assigns them FP4 (1 sign bit, 2 exponent bits, 1 mantissa bit), providing exponential representation spacing that preserves tail features. 3. Cross-Module Co-Optimization: Instead of quantizing layers in isolation, CoOpQ solves a joint optimization objective where the scaling factors of the attention block and MLP block are co-tuned against a shared reconstruction loss. 4. Fused Mixed-Precision Kernels: A single fused CUTLASS kernel manages dual-format execution without host-to-device memory round-trips.

    The Math (Light)
