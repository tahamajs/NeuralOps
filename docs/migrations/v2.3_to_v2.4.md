# Migration Guide: NeuralOps v2.3 → v2.4.0

> **Estimated migration time:** 30 minutes for most projects.  
> **Breaking changes count:** 4 (see [BREAKING_CHANGES.md](../../BREAKING_CHANGES.md))

---

## Overview of v2.4.0 Architecture

NeuralOps v2.4.0 introduces three major subsystems that modernize and replace legacy entrypoints while preserving backward compatibility through transparent shims:
- **`cli_v2/`**: Modular CLI with lazy subcommand dispatch (`neuralops benchmark`, `neuralops serve`, `neuralops matrix`, `neuralops surgery`).
- **`config_v2/`**: Pydantic v2 strictly validated YAML configuration engine with frozen data models and fail-fast validation.
- **`results_v2/`**: Atomic multi-format persistence ledger (`BenchmarkLedger`) delivering simultaneous atomic writes to Parquet, JSONL, SQLite, Markdown scorecards, and canonical JSON records.

Additionally, v2.4.0 hardens the runtime against common ML system failures:
- Strict adoption of standard PyTorch 2.x `torch.amp` (Rule 2.1).
- Mandatory safe tensor deserialization with `weights_only=True` (CVE protection).
- Fail-closed execution semantics with the `BenchmarkStatus` enum (Rule 4.2).

## Recipe 1: Upgrading CLI Benchmark Invocations

### Before (v2.3)
In v2.3, benchmarks were executed by invoking the monolithic `benchmarks.cli` module directly via `python -m`:
```bash
python -m neuralops.benchmarks.cli --suite attention --model qwen
```

### After (v2.4)
In v2.4, benchmark execution routes through the consolidated `neuralops` CLI entrypoint using structured YAML configurations:
```bash
neuralops benchmark run --config configs/attention_sweep.yaml --dry-run
```

### Automated shim (backward-compat wrapper)
If you have automated CI/CD jobs or legacy shell scripts that cannot immediately migrate to the new subcommand syntax, you can pass legacy configs through the unified CLI:
```bash
# If you cannot immediately migrate, use the legacy shim:
neuralops benchmark --config <your-legacy-shim>.yaml
```
Invoking `neuralops.benchmarks.cli.main()` directly now emits a `DeprecationWarning` and delegates execution seamlessly to `cli_v2.main:main`.

## Recipe 2: Upgrading Benchmark Configurations

### Before (v2.3) — untyped dict
In v2.3, configs were loaded using raw `yaml.safe_load`, leaving fields untyped and missing type or boundary verification:
```python
import yaml
from neuralops.benchmarks.runner import run_benchmark

config = yaml.safe_load(open("benchmark.yaml"))
run_benchmark(config["suite"], config["kernels"])
```

### After (v2.4) — Pydantic v2 validated
In v2.4, all configuration loading goes through `config_v2.loader.load_benchmark_config`. The returned configuration is an immutable, strictly typed Pydantic v2 model:
```python
from neuralops.benchmarks.config_v2.loader import load_benchmark_config
from neuralops.benchmarks.runner import run_benchmark

config = load_benchmark_config("benchmark.yaml")
# config is now a frozen, type-safe KernelSuiteConfig object
run_benchmark(config.suite, config.kernels)
```

**Benefits:**
- Detects misspelled YAML keys instantly before launching GPU workloads.
- Provides informative error messages showing exact YAML keypaths (e.g. `suites[0].kernels[2]`).
- Immutable: prevents accidental in-place mutation during distributed sweeps.

## Recipe 3: Upgrading Model Surgery & Checkpoints

### Before (v2.3)
In v2.3, surgery and checkpoint serialization were tightly coupled in monolithic helper functions:
```python
import torch
from neuralops.surgery import replace_and_save

model = torch.nn.Linear(256, 256)
replace_and_save(model, attention_type="cosformer", output_path="model.pt")
```

### After (v2.4)
In v2.4, surgery and serialization are decoupled into modular APIs. Universal surgery is performed via `replace_attention`, and minimal weight deltas are isolated and exported via `save_surgical_delta`:
```python
import torch
from neuralops.api import replace_attention, save_surgical_delta

model = torch.nn.Linear(256, 256)
model = replace_attention(model, attention_type="cosformer")
save_surgical_delta(model, base_model_path="base/", output_path="delta.pt")
```

**Benefits:**
- **Zero Full Weight Duplication:** Surgical deltas store only modified parameters (e.g., projection matrices and kernel coefficients), cutting storage requirements by up to 95%.
- **Universal Director:** Compatible with HuggingFace AutoModel, Transformer blocks, and custom modular architectures.

## Recipe 4: Upgrading Serving & Batch Inference

### Before (v2.3)
In v2.3, continuous batching and sequential generation were exposed through legacy adapter methods:
```python
from neuralops.serving.adapter import ServingAdapter

adapter = ServingAdapter()
prompts = ["NeuralOps high performance inference", "Attention kernel benchmark"]
output = adapter.continuous_batching_generate(prompts, max_new_tokens=256)
```

### After (v2.4)
In v2.4, batch generation uses the standardized, deterministic `generate_sequential` method or the modern `TGIServingAdapter`:
```python
from neuralops.serving.adapter import ServingAdapter

adapter = ServingAdapter()
prompts = ["NeuralOps high performance inference", "Attention kernel benchmark"]
output = adapter.generate_sequential(prompts, max_new_tokens=256)
```

**Lifecycle Note:** `continuous_batching_generate` is retained as a deprecated alias emitting a `DeprecationWarning` and will be permanently removed in `v2.6.0`.

## Recipe 5: PyTorch 2.x AMP Modernization & Safe Deserialization

### Before (v2.3) — Deprecated CUDA AMP & Unsafe Deserialization
```python
import torch
from torch.cuda.amp import autocast, GradScaler

# Unsafe weights loading vulnerable to arbitrary code execution
weights = torch.load("model_checkpoint.pt")

# Deprecated device-specific autocast
scaler = GradScaler()
with autocast(dtype=torch.float16):
    outputs = model(inputs)
```

### After (v2.4) — Standard `torch.amp` & `weights_only=True`
```python
import torch
from torch.amp import autocast, GradScaler

# Safe deserialization conforming to CVE protection guidelines
weights = torch.load("model_checkpoint.pt", weights_only=True)

# Device-agnostic PyTorch 2.x AMP
scaler = GradScaler("cuda", enabled=torch.cuda.is_available())
device_type = "cuda" if torch.cuda.is_available() else "cpu"
with autocast(device_type, dtype=torch.float16):
    outputs = model(inputs)
```

## Recipe 6: Benchmark Results & Ledger Persistence

### Before (v2.3) — Ad-hoc dict results
```python
results = {
    "status": "PASS",
    "latency": 1.42,
    "throughput": 850.0,
}
with open("results.json", "w") as f:
    import json
    json.dump(results, f)
```

### After (v2.4) — Strongly Typed `CanonicalRecord` & `BenchmarkLedger`
```python
from neuralops.benchmarks.results_v2.ledger import BenchmarkLedger
from neuralops.benchmarks.results_v2.record import CanonicalRecord
from neuralops.benchmarks.results_v2.status import BenchmarkStatus

record = CanonicalRecord(
    run_id="run_20261115_001",
    timestamp="2026-11-15T12:00:00Z",
    git_commit="b67e84f1e0",
    git_dirty=False,
    suite="attention_sweep",
    module="svd_linear",
    model="qwen",
    dataset="synthetic",
    device="cuda:0",
    status=BenchmarkStatus.SUCCESS.value,
    metrics={"latency_ms": 1.42, "throughput_tok_s": 850.0},
    config={"batch_size": 4, "seq_len": 2048},
    telemetry={"peak_gpu_mem_mb": 4120.0},
    checksum="e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
)

ledger = BenchmarkLedger(base_dir="results")
ledger.write(record)
```

## Automated Migration Script

You can run the automated migration script `scripts/migrate_v23_to_v24.py` across your codebase to automatically patch deprecated function names and config loaders:

```python
# scripts/migrate_v23_to_v24.py
import re
import sys

def migrate_file(path: str) -> None:
    with open(path) as f:
        content = f.read()

    # Migrate serving method
    content = content.replace(
        "continuous_batching_generate",
        "generate_sequential",
    )

    # Migrate deprecated AMP imports
    content = content.replace(
        "from torch.cuda.amp import autocast, GradScaler",
        "from torch.amp import autocast, GradScaler",
    )

    # Migrate YAML loaders
    content = re.sub(
        r'yaml\.safe_load\(open\(["\']([^"\']+)["\']\)\)',
        r'load_benchmark_config("\1")',
        content,
    )

    with open(path, "w") as f:
        f.write(content)
    print(f"Migrated: {path}")

if __name__ == "__main__":
    for path in sys.argv[1:]:
        migrate_file(path)
```
