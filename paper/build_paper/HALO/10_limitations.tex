
\section{Limitations}

\subsection{No Speedup Without Hard Routing}

HALO-ReGLA computes \textbf{both} dense and linear streams. Without a post-training 
hard routing step, no speedup is realized. This is the main limitation.

\subsection{No Parameter Reduction}

HALO-ReGLA adds gate parameters ($dH + H \approx 9K$). Total parameter count 
increases slightly.

\subsection{Task Coverage}

Only SST-2 evaluated. Long-context tasks not tested.

\subsection{Model Coverage}

Not tested on:
\begin{itemize}
\item Large models ($H > 32$)
\item Mixture-of-Experts
\item Vision transformers

\end{itemize}
\subsection{Cumsum Memory}

The causal cumsum allocates an $\mathcal{O}(L d_h^2)$ intermediate. For 
$L = 8192$, $d_h = 64$: ~$130$ MB per head, ~1.6 GB per layer for 12 heads. 
This is prohibitive.

\textbf{Future work:} Chunked cumsum or recurrent state passing.

\subsection{Fixed Kernel}

We use a fixed $\phi = \mathrm{elu} + 1$. Learned kernels could be better.

\subsection{Single Seed}

All results from seed 42.

\subsection{No Comparison with Some Baselines}

We do not compare with:
\begin{itemize}
\item FLASH
\item GLA
\item H-Transformer

\end{itemize}
\subsection{Failure Modes}

Long-context cumsum memory

\subsection{Code Quality}

Research-grade. Numerical stability issues at extreme $L$.
