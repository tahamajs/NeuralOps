
\section{9. Discussion}

\subsection{9.1 Key Takeaways}

\subsubsection{9.1.1 Takeaway 1: Token Pruning is Effective}

At $\rho = 0.8$, PTP achieves \textbf{1.25$\times$} speedup with 
only \textbf{-1.2\%} accuracy drop.

\subsubsection{9.1.2 Takeaway 2: [CLS] Preservation is Essential}

Without [CLS] preservation, accuracy drops by \textbf{15\%}.

\subsubsection{9.1.3 Takeaway 3: Learned Scores Reveal Structure}

The MLP learns a task-specific importance measure that correlates with 
content-word importance.

\subsection{9.2 When to Use PTP}

\subsubsection{Recommended}

\begin{itemize}
\item \textbf{Long-sequence classification} (document sentiment, topic)
\item \textbf{Retrieval-augmented generation} (prune retrieved passages)
\item \textbf{Edge deployment} where latency matters
\end{itemize}

\subsubsection{Not Recommended}

\begin{itemize}
\item \textbf{Very short sequences} ($L < 32$)
\item \textbf{Generation tasks} (token order matters)
\item \textbf{Tasks requiring full context} (long-form QA)
\end{itemize}

\subsection{9.6 Open Questions}

1. \textbf{Per-head scoring:} Should each head have its own score network?
2. \textbf{Learned $\rho$:} Can we learn the keep ratio?
3. \textbf{Cross-layer sharing:} Share the score network across layers?
4. \textbf{Long-context scaling:} How does PTP scale at $L = 4096$?

\subsection{9.7 Broader Impact}

\subsubsection{Positive}
\begin{itemize}
\item \textbf{Faster inference:} Reduces compute per token.
\item \textbf{Lower memory:} Attention memory scales with $k$.
\item \textbf{Interpretability:} Token importance is visible.
\end{itemize}

\subsubsection{Negative}
\begin{itemize}
\item \textbf{Dual-use:} Efficiency gains benefit malicious applications.
\item \textbf{Concentration:} Favors large labs.
\end{itemize}

\subsubsection{Environmental}
