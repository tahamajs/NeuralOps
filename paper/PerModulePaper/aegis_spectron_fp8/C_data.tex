 4.2 Diagnostic Case Study 1: Resolving FP16 Overflow in Linear Attention

 Problem Statement
During initial encoder testing under PyTorch `torch.autocast('cuda', dtype=torch.float16)`, training instantly collapsed at Step 1 with `loss = nan`.

 Root Cause Analysis
In the bidirectional global linear attention branch:
$$\operatorname{Num} = \Phi\_Q \left(\Phi\_K^\top V\right) \in \mathbb{R}^{B \times N \times D}$$
Because the ELU kernel $\Phi(x) = \operatorname{ELU}(x) + 1.0$ is strictly positive, the intermediate associative state $KV = \Phi\_K^\top V$ accumulated strictly positive quantities over sequence length $N=64$ and hidden dimension $D=768$.
When calculating $\Phi\_Q \cdot (KV)$, internal tensor values reached **$116,811.6$**.
In IEEE-754 Half Precision (FP16), the maximum representable finite value is **$65,504$**.
Although Python variables were cast with `.float()`, PyTorch's automatic mixed precision context intercepted `torch.matmul` and implicitly downcast inputs back to FP16, resulting in overflow to `+inf`, subsequent `inf / inf` division, and fatal `NaN` propagation.

 Mathematical Resolution
1. **Explicit Autocast Deactivation**: Wrapped all associative matrix multiplications and normalization products inside an explicitly disabled autocast context:
   ```python
   device\_type = Q.device.type if Q.device.type in ("cuda", "cpu") else "cuda"
   with torch.autocast(device\_type=device\_type, enabled=False):
       phi\_Q\_f = phi\_Q.float()
       phi\_K\_f = phi\_K.float()
       V\_f = V\_flat.float()
       KV = torch.matmul(phi\_K\_f.transpose(-1, -2), V\_f)
       Z = phi\_K\_f.sum(dim=1, keepdim=True)
       num = torch.matmul(phi\_Q\_f, KV)
       den = torch.matmul(phi\_Q\_f, Z.transpose(-1, -2)) + 1e-6
       out\_lr = (num / den).to(Q.dtype) / math.sqrt(self.config.svd\_rank)
   ```
2. **FP32 Dequantization Scaling**: In `fp8\_cast\_simulate`, scale division was forced to execute strictly in `float32`:
   ```python
   x\_dequant = (x\_fp8.float() / scale.float()).to(orig\_dtype)
   ```
   preventing extremely large scaling factors from overflowing FP16 to `+inf` and zeroing activations.

 4.3 Diagnostic Case Study 2: Lagrangian Router Prior Initialization Ablation

 Problem Statement
In an initial test run after fixing the FP16 overflow, DistilBERT and RoBERTa converged smoothly without `NaN`, but stagnated at exactly **50.92%** accuracy (`PASS\_LOW`), whereas GPT-2 achieved **79.82%**.

 Root Cause Analysis
1. **SST-2 Label Distribution**: The SST-2 validation dataset consists of 872 samples (444 negative, 428 positive). A trivial constant predictor guessing the majority class achieves:
   $$\frac{444}{872} = 50.9174\% \approx 50.92\%$$
   The encoders had collapsed to predicting constant negative labels.
2. **Lagrangian Cost Penalty Imbalance**:
   The router computes logits via:
   $$\mathbf{z}\_t = \frac{H\_b \cdot \mathcal{S}(x\_t) - \lambda \mathbf{c}}{\tau}, \quad \mathbf{c} = [1.0, 0.5, 0.1]^\top$$
   Because the local branch cost was $1.0$ and the linear recurrence cost was $0.1$, the penalty heavily penalized local attention. At initialization with unbiased router logits, the router directed **~80% of attention weight to the linear recurrence branch** ($\alpha\_{\text{lin}}$) and only **~10% to the local branch** ($\alpha\_{\text{loc}}$).
3. **Signal Magnitude Disparity**:
   - `\_local\_branch` preserved pretrained attention patterns with activation magnitude $\approx 5.0$.
   - `\_linear\_branch` evaluated an untrained bidirectional recurrence whose activation magnitude reached $\approx \mathbf{77.0}$.
   Routing 80% of the attention through an untrained 77-magnitude linear recurrence completely drowned out the pretrained linguistic syntax, destroying contextual representations at Step 1.

 Resolution \& Verification
Configured the default router bias prior in `AegisSpectronFP8Config`:
```python
router\_init\_bias: Tuple[float, float, float] = (2.0, 0.0, -1.0)
```
- Local bias ($+2.0$) guarantees that at Step 0, $\alpha\_{\text{loc}} \ge 90\%$, preserving the exact pretrained self-attention within the window ($W=64$).
- Global ($0.0$) and Linear ($-1.0$) branches act as residual perturbations that are gradually activated as the router learns semantic entropy distributions.

**Ablation Results**:
- DistilBERT without prior bias: **50.92%** (stagnant majority-class collapse)
- DistilBERT with `router\_init\_bias = (2.0, 0.0, -1.0)`: **84.86%** (**+33.94% absolute accuracy gain!**)

 4.4 Diagnostic Case Study 3: The Nested Encoder Double-Projection Pathology in RoBERTa

 Problem Statement
While DistilBERT recovered to **84.86%** and GPT-2 to **80.16%** with the router prior bias, RoBERTa remained trapped at **50.92%** (`PASS\_LOW`), with training loss stagnating and climbing between $0.70$ and $1.25$.

 Root Cause Analysis: Architectural Discrepancy \& Double Output Projection
A systematic trace of RoBERTa's tensor flow uncovered a critical architectural distinction between flat and nested transformer blocks:

1. **Flat Architecture (DistilBERT, GPT-2, Qwen):**
   The attention module is self-contained, holding both the dot-product computation and the linear output projection (`out\_lin`, `c\_proj`, or `o\_proj`). Replacing the module replaces both stages simultaneously.

2. **Nested Architecture (RoBERTa \& BERT):**
   HuggingFace divides attention into two cascaded sub-modules:
   ```
   RobertaAttention
   +-- self: RobertaSelfAttention          <-- [Target of inject\_attention]
   +-- output: RobertaSelfOutput           <-- [Holds outer dense + LayerNorm]
         +-- dense: Linear(768, 768)
         +-- LayerNorm: LayerNorm(768)
         +-- dropout: Dropout(0.1)
   ```
   In native RoBERTa, `RobertaSelfAttention` computes attention weights and values and returns `context\_layer` directly *without* an output projection. The parent container's `RobertaSelfOutput.dense` then applies the linear projection.

3. **The Attribute Injection Masking Bug:**
   In `aegis\_spectron\_fp8.py`, a safety check was intended to bypass the internal output projection for nested encoders:
   ```python
   cls\_name = old\_attn.\_\_class\_\_.\_\_name\_\_
   has\_out\_proj = any(hasattr(old\_attn, attr) for attr in ("dense", "out\_proj", ...))
   if (cls\_name in ("BertSelfAttention", "RobertaSelfAttention") ...) and not has\_out\_proj:
       self.is\_nested\_encoder = True
   ```
   However, the framework's universal injection adapter (`attention\_utils.py`) pre-emptively attaches proxy `dense` and `out\_proj` attributes to `old\_attn` before passing it to the constructor. Consequently:
   - `has\_out\_proj` evaluated to `True`.
   - `self.is\_nested\_encoder` was set to `False`.
   - `old\_attn.\_\_class\_\_.\_\_name\_\_` was wrapped as `UniversalAttentionWrapper`.

4. **The Mathematical Double-Projection ($W\_{\text{dense}}^2$):**
   Because `is\_nested\_encoder` was `False`, `aegis\_spectron\_fp8` executed its own internal output projection:
   $$\mathbf{y}\_{\text{internal}} = \text{self.out\\_proj}(\mathbf{y}\_{\text{fused}}) = W\_{\text{out\\_proj}} \cdot \mathbf{y}\_{\text{fused}}$$
   where $W\_{\text{out\\_proj}}$ was initialized via SVD of RoBERTa's `output.dense`.
   Then, the parent container `RobertaSelfOutput` received $\mathbf{y}\_{\text{internal}}$ and executed:
   $$\mathbf{y}\_{\text{final}} = \operatorname{LayerNorm}\left( W\_{\text{dense}} \cdot \mathbf{y}\_{\text{internal}} + \mathbf{x} \right) = \operatorname{LayerNorm}\left( W\_{\text{dense}} \cdot W\_{\text{dense}} \cdot \mathbf{y}\_{\text{fused}} + \mathbf{x} \right)$$
   The dense transformation was applied **twice in series**.

 Quantitative Empirical Verification on Physical Hardware
We executed a layer-by-layer tensor trace on Layer 0 of RoBERTa-base:
- Pretrained `RobertaSelfAttention` output magnitude: $\text{mean absolute} = \mathbf{0.1297}$
- `aegis\_spectron\_fp8` fused attention before `out\_proj`: $\text{mean absolute} = \mathbf{0.0980}$ (cosine similarity = **0.7515**)
- `aegis\_spectron\_fp8` output after internal `out\_proj`: $\text{mean absolute} = \mathbf{0.01395}$ (**7\times  attenuation**)
- Outer residual connection magnitude ($\mathbf{x}$): $\text{mean absolute} \approx \mathbf{16.0}$

Because the attention output was attenuated by $7\times$ down to $\approx 0.014$, its contribution to the LayerNorm sum $(\mathbf{x} + \mathbf{y})$ was less than $0.1\%$. Across all 12 layers, contextual token interaction was silenced, turning RoBERTa into an identity residual pipe.

 Compounding Factor: Missing Pretrained Classification Head
Unlike `models/distilbert\_sst2` (which ships with a pre-trained SST-2 head, 90.48% baseline) and GPT-2 (pre-fine-tuned LoRA baseline, 81.31%), `models/roberta-base` is a raw masked-LM checkpoint without an SST-2 classification head (`classifier.dense` and `classifier.out\_proj` are randomly initialized from $\mathcal{N}(0, 0.02)$).
Faced with an attenuated 0.1% attention signal and a high recovery learning rate (`2e-4`), the optimizer drifted into the trivial majority-class minimum: predicting constant negative labels ($444/872 = \mathbf{50.92\%}$).

 Architectural Remedy \& Validation
1. **Explicit Nested Encoder Recognition**: Updated the detection logic to identify nested self-attention modules by checking parent container hierarchy (`"self"` submodule inside a container with `output.dense`) or model family (`"roberta"` / `"bert"` without native `out\_lin`), ensuring `is\_nested\_encoder = True` regardless of monkey-patched attributes.
2. **Identity Pass-Through**: When `is\_nested\_encoder = True`, `final\_out = out\_fused` is returned directly, allowing the parent's `output.dense` to perform the single, correct output projection.

 4.5 Diagnostic Case Study 4: Qwen3.5-0.8B Timeout, Recovery Rate & 24-Layer Sublinear Scaling

 Problem Statement
In the initial multi-model sweep, Qwen3.5-0.8B was terminated prematurely at Step 95/200 by the framework's hardcoded 600-second stall timer, despite loss descending rapidly ($4.60 \to 0.57$).

 Root Cause Analysis
1. **Computational Workload Across 24 Layers:**
   Unlike 6-layer DistilBERT or 12-layer GPT-2/RoBERTa, Qwen3.5-0.8B has 24 decoder layers with Grouped-Query Attention (GQA, 8 query heads, 2 KV heads, $d\_{\text{head}}=256$) and Rotary Position Embeddings (RoPE). Under batch size 8 with micro-batch accumulation ($bs=4$), each training step on the RTX 4070 Laptop GPU required $\approx 6.5$ seconds. Reaching 200 recovery steps requires $\approx 1,300$ seconds, guaranteeing a timeout under a 600-second window.
2. **Learning Rate Misclassification:**
   Because Qwen3.5 hidden size exceeds 512 ($D=1024$), the default sweep logic fell back to a conservative fine-tuning rate of $5 \times 10^{-5}$. However, hybrid attention modules with newly initialized state parameters (EMA decay $\gamma$, linear state projections, and spectral entropy routers) require a scratch recovery learning rate ($2 \times 10^{-4}$) to escape early saddle points.

 Resolution \& Verification
1. **Timeout Override**: Added `"aegis\_spectron\_fp8": 1500` to `\_SLOW\_MODULE\_TIMEOUT\_OVERRIDES` in `Codes/framework/run\_quality\_sweep.py`.
2. **From-Scratch Learning Rate**: Registered `"aegis\_spectron\_fp8"` in `FROM\_SCRATCH\_MODULES`, enforcing `rec\_lr = 2e-4`.
3. **Empirical Convergence**:
   - Step 1: `loss = 3.6045`
   - Step 35: `loss = 0.6085`
   - Step 100: `loss = 0.6983`
   - Step 155: `loss = 0.4395`
   - Step 200: `loss = 0.5804`
   - Final Evaluated Accuracy: **59.29%** (**PASS**, exceeding the statistical significance threshold of 56.00% by $+3.29\%$).

2. \textbf{Learning Rate Misclassification:}
