\subsection{Weight Transfer}

Standard four-architecture copy with additional factorization step:

\begin{lstlisting}
with torch.no_grad():
    for proj_key, target_mod in target_map.items():
        w, b = extracted[proj_key]
        if w is None:
            continue
        if w.ndim != 2:
            w = w.reshape(w.size(0), -1)
        if w.shape != (target_mod.out_features, target_mod.in_features) \
           and (target_mod.out_features, target_mod.in_features) == w.t().shape:
            w = w.t()
        target_mod.decompose_from_weight(w[:target_mod.out_features, :target_mod.in_features], ...)
\end{lstlisting}

The \texttt{decompose\_from\_weight} method:
\begin{enumerate}
\item Computes SVD.
\item Selects rank by energy threshold.
\item Sets \texttt{down.weight = $\Sigma$^{1/2} V^T}, \texttt{up.weight = U $\Sigma$^{1/2}}.

\end{enumerate}

\subsection{The `copy\_weights` Failure Path}

\textbf{Case 1: UniversalAdapter succeeds for all projections.}
\begin{itemize}
\item Standard extraction works.
\item No issue.

\end{itemize}
\textbf{Case 2: UniversalAdapter fails, but the direct extraction already succeeded.}
\begin{itemize}
\item \texttt{missing} is empty $\to$ no try/except triggered.
\item No issue.

\end{itemize}
\textbf{Case 3: UniversalAdapter raises.}
\begin{itemize}
\item \texttt{raise RuntimeError} aborts \texttt{copy\_weights}.
\item \texttt{inject\_orion} catches it (the outer try/except) $\to$ returns None.
\item \textbf{Safe} -- the module is not installed.

\end{itemize}
\textbf{Case 4: UniversalAdapter returns None for all \texttt{missing}.}
\begin{itemize}
\item \texttt{missing\_after} is non-empty $\to$ RuntimeError.
\item Same as case 3.

\end{itemize}
\textbf{Case 5: UniversalAdapter raises but injection proceeds anyway.}
\begin{itemize}
\item Not possible -- \texttt{inject\_orion} has its own try/except.

\end{itemize}

\subsection{Common Pitfalls}

\subsubsection{`FactorisedLinear.weight` Materializes Full Matrix}

\begin{lstlisting}
@property
def weight(self):
    return torch.matmul(self.up.weight, self.down.weight)
\end{lstlisting}

For 768$\times$768 this is fine. For 3072$\times$768 with rank 64: \texttt{64 $\times$ 3072 + 64 $\times$ 768} 
= 245K params, materializing to 2.36M -- a 10$\times$ overhead. Used in Frobenius 
check inside \texttt{copy\_weights}.

\subsubsection{The `raise` Bug}

See Section 4.10.

\subsubsection{Softpick Masked Rows}

As noted, if a row is entirely masked, output is zero.

\subsubsection{The `\_kernel\_linear\_attention` Python Loop (Decoder)}

For $N = 128$, chunk\_size = 64: 2 iterations. Acceptable but not 
vectorized.

\subsubsection{`rff\_proj` is not persistent}

\begin{lstlisting}
self.register_buffer("rff_proj", torch.randn(...), persistent=False)
\end{lstlisting}

With \texttt{persistent=False}, \texttt{rff\_proj} is not saved in \texttt{state\_dict()}. On 
reload, it is re-initialized randomly. \textbf{This is a bug} -- the RFF 
projection must be preserved.
