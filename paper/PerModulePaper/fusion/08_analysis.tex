\section{Analysis}

\subsection{The Short-Path Problem}

\textbf{Critical insight.} FUSIONATTN's dispatch threshold is $L_\text{threshold} = 128$. 
Our test dataset (SST-2) uses $L = 128$. The condition:

\begin{lstlisting}
if N <= 128 or is_cross_attention:
    # short path
\end{lstlisting}

\textbf{Always selects the short path.} Therefore:

\begin{enumerate}
\item \textbf{No sparsity is applied.}
\item \textbf{Gate MLP is never used.}
\item \textbf{Only LoRA contributes trainable capacity.}
\item \textbf{The model is effectively just a LoRA-wrapped baseline.}

\end{enumerate}
This is not a flaw of FUSIONATTN -- it's the intended behavior. But at 
$L = 128$, the module's sparsity machinery is silent.

\subsection{Summary of Insights}

\begin{enumerate}
\item \textbf{Short path is silent at L=128} -- no sparsity benefit.
\item \textbf{Long path untested} -- requires L > 128.
\item \textbf{Parameter count increases} -- LoRA + gate.
\item \textbf{Not a compression method.}
\item \textbf{Theoretical speedup} exists for L $\ge$ 256.

\end{enumerate}
