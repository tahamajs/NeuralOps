# NeuralOps Experimental Results Repository

This repository stores all empirical benchmark logs, checkpoint metadata, evaluation metrics, and comparative artifacts generated by the SVD & Linear Attention Framework across multiple model architectures, language modeling tasks, and reasoning benchmarks.

---

## 1. Directory Structure & Organization

The `results/` hierarchy contains 268 experimental suites partitioned into functional categories:

### A. Reasoning & Zero-Shot Evaluations
* **`zeroshot_parallel/`**: **Canonical Zero-Shot Reasoning Suite** evaluating 183 compression and attention modules on GPT-2 across 5 reasoning benchmarks:
  - `piqa`, `arc_easy`, `arc_challenge`, `hellaswag`, `winogrande`.
  - Each module folder contains 11-12 standardized artifacts:
    - `<task>.json`: Summary task metrics (accuracy, sample counts, timing).
    - `<task>_detailed.json`: Complete per-sample predictions, logits, and answers.
    - `<module>_zeroshot.json`: Macro aggregated metrics across all 5 benchmarks.
    - `run_metadata.json`: Machine hardware specs, versions, execution time.
    - `run.log`: Standard output execution trace.
* **`zeroshot/`**: Early exploratory zero-shot evaluation runs.

### B. Standard GLUE & Classification Sweeps
* **`distilbert_*` / `bert_*`**: Bidirectional encoder evaluations across classification tasks (`sst2`, `mnli`, `agnews`, `rte`).
* **`roberta_*`**: RoBERTa baseline and fine-tuning recovery runs.
* **`rank_sweep_mnli/`** & **`rank_sweep_agnews/`**: Systemic rank sweep evaluations (ranks 64, 128, 256, 384) on DistilBERT.
* **`batch2_distilbert/`**, **`batch2_roberta/`**, **`batch3_distilbert/`**, **`batch3_roberta/`**: Multi-batch module test runs.

### C. Autoregressive Language Modeling & Perplexity (PPL)
* **`c4_baselines/`**: GPT-2 validation perplexity sweeps on the C4 benchmark across rank variations.
* **`gpt2_c4_ppl/`**: C4 evaluation runs measuring perplexity degradation.
* **`gpt2_wikitext2_sweep/`** & **`wikitext/`**: WikiText-2 validation perplexity and token loss logs.
* **`long_context/`** & **`seqlen_scaling/`**: Sequence-length scaling benchmarks (512 to 8192 tokens) measuring throughput and memory.

### D. Statistical Rigor & Reproducibility
* **`multiseed/`**, **`multiseed_rigor_distilbert/`**, **`multiseed_rigor_roberta/`**: Multi-seed evaluations (seeds 42, 123, 456, 789, 999) verifying variance, mean accuracy, and F1 scores.

### E. Unified Full Matrix & Historical Archives
* **`Unified/`**: Unified evaluation repository containing 237 module subdirectories across multiple architectures.
* **`archive_unified/`** & **`benchmark_results_archived/`**: Archived earlier experimental iterations.
* **`_archive_partial/`**: Temporary archive of partial/in-flight runs.

## 2. Master Aggregation Tables (Root Directory)

* **`benchmark_summary_v2.csv`**: Comprehensive multi-model, multi-dataset benchmark summary table.
* **`master_aggregated_results.csv`**: Master verified table aggregating accuracies, F1 scores, parameters, and compression ratios.
* **`master_benchmark_summary.csv`** & **`master_benchmark_summary.json`**: Top-tier Pareto frontier candidates.
* **`all_121_compressors_gpu_matrix.csv`** & **`all_compressors_gpu_summary.csv`**: GPU compatibility and compression ratios.
* **`SEQLEN_SCALING_MASTER.csv`**: Latency and peak VRAM benchmarked across token sequence lengths.
* **`FULL_BENCHMARK_ANALYSIS_REPORT.md`**: Detailed textual analysis of architecture-level compression performance.

---

## 3. Data Integrity & Maintenance Rules

1. **No Temporary Files**: `.DS_Store`, `*.bak`, `*.tmp`, and editor swap files must never be checked in.
2. **Standard Output Artifacts**: Every complete module run must provide summary JSON, detailed predictions JSON, and execution logs.
3. **Reproducibility**: Parameter deltas, compression rates, and random seeds are recorded in `run_metadata.json`.
